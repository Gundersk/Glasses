# Среда: что есть и чего не хватает

Базовый снимок 06.11.2026; уточнения 13.11 ниже. Диск/версии в старом снимке
не являются повторным замером текущего состояния.

## Актуальные ограничения (13.11.2026)

- Железо владельца: Windows, i7-11700KF, **64 ГБ DDR4**, RX 7700 XT 12 ГБ
  (`gfx1101`). CUDA нет. CPU — проверенный путь прототипа; ускорение не измерялось.
- Проверка 12.11: `onnxruntime 1.31.1`, провайдеры CPU/Azure; `torch` и `pyannote`
  не установлены. У `sherpa-onnx 2.0.1` provider cpu/cuda/coreml, не DirectML.
  `onnxruntime-directml` не ставить в рабочую `.venv`: отдельная среда и опыт.
- S069: RX 7700 XT есть в **Linux ROCm 6.4.4**. Windows PyTorch matrix **6.4.4**
  перечисляет gfx1201/gfx1200/gfx1100, не gfx1101. Ревью ошибочно перенесло Linux
  на Windows preview. Более поздняя поддержка требует отдельной проверки точной
  ОС/GPU/PyTorch; это не заявление, что Windows GPU невозможен вообще.
- Поддержка PyTorch/ROCm не означает поддержку ONNX/sherpa-onnx и не доказывает
  ускорение NeMo/диаризации. Установка/смена ОС/драйверов здесь не выполнялась.
- Поиск уже встроен в ворота критика (до 3 запросов в одном раунде) и в отдельное
  задание ментора (`autonomy/intake.py`, до 3 запросов × 2 страницы, `--fresh`).
  Это опровергает старое «поиск не встроен» ниже; качество живого маршрута не проверено.
- Регрессионные тесты запускаются `.venv\Scripts\python.exe` (Python 3.12.15),
  а не системным Python. Текущие артефакты проверки — `docs/audits/2026-11-13/`.

## Поиск и исследования — исторический снимок 10.11

Проверено 2026-11-10.

- В сессии OpenCode доступны Exa (`web_search_exa`, `web_fetch_exa`) и Context7 (`resolve-library-id`, `query-docs`). В этой проверке запросы к ним не выполнялись; это инструменты интерактивной сессии, а не подтверждённая часть автономного раннера.
- `autonomy/research.py` реализует клиент TinyFish MCP с методами `search` и `fetch`. `autonomy/runner.py` импортирует модуль `research` (строка 16), но не создаёт `TinyFish` и не вызывает эти методы. Контекстный поиск в автономный цикл не встроен.
- Переменная `TINYFISH_API_KEY` доступна через `autonomy.env.get`, включая загрузку из `.env`. Значение ключа не проверялось и не записывалось в документы.
- Один реальный smoke-запрос через `TinyFish.search` с конфигом `autonomy/config.yaml` завершился успешно: 10 результатов за 7.651 с. Проверялся только прямой вызов клиента, без запуска ночного цикла. Метод `fetch` и устойчивость сервиса не проверялись.
- Кэш находится в `autonomy/workspace/cache/web`. Результаты поиска хранятся в JSON и считаются свежими 7 суток, страницы - 3 суток. При свежем попадании в кэш сетевой поиск не выполняется.
- HTTP-таймаут одного MCP-вызова в клиенте - 120 с. В `autonomy/config.yaml` указаны пределы 3 поиска и 5 страниц на задачу, но их применение раннером не подтверждено, потому что соответствующих вызовов в нём нет.

## Бесплатные модели Google (проверено 2026-11-11)

- В `.env` два ключа Google AI Studio от разных аккаунтов: `GEMINI_API_KEY` и `GEMINI_API_KEY_ALT`. В `autonomy/config.yaml` они подключены как четыре провайдера: `gemini_free`, `gemini_lite_free`, `gemini_alt`, `gemini_lite_alt`. Второй аккаунт нужен потому, что бесплатная квота считается на аккаунт, а не на ключ.
- Работоспособность подтверждена журналом `autonomy/workspace/events.jsonl`: ночью 09.11 через `gemini_free` и `gemini_lite_free` прошло 23 вызова (10 и 13). Это тот же Python-клиент `autonomy/providers.py`, который работает в ночном цикле.
- Отдельная проверка 11.11.2026 из песочницы Code Mode через голый `fetch` вернула HTTP 400 `FAILED_PRECONDITION: User location is not supported` для обоих ключей. Этот результат **не относится к проекту**: запрос из песочницы не шёл через VPN, в отличие от OpenCode и Python. Ошибка относилась к IP, а не к ключам и не к квоте.
- Вывод: для ночного цикла нужен включённый VPN, как и для OpenRouter. Без него падают оба облачных пути, а не только Google.
- Что не проверено: второй ключ `GEMINI_API_KEY_ALT` в реальном вызове ещё не участвовал. Первый вызов через него в ночи надо сверить с `events.jsonl`.

## Не установлено / требует решения

| Что | Зачем | Как поставить |
|---|---|---|
| `pyannote.audio` + веса | диаризация | нужен Hugging Face аккаунт, принятие условий и `HF_TOKEN` |
| `torch` (CPU) | pyannote/WhisperX | ставить CPU-сборку; CUDA не будет |
| `onnxruntime-directml` | попытка задействовать AMD GPU | экспериментально; проверить скорость и совместимость |
| `faster-whisper` / `whisper.cpp` | альтернативные ASR-движки | для сравнения на одном аудио |
| `jiwer` / `pandas` | WER и таблицы | для baseline-эксперимента |
| Hugging Face token | gated-модели (pyannote Community-1 и др.) | создать токен, положить в переменную `HF_TOKEN` |
| Tavily key (опционально) | второй поисковик | если Exa не хватает |
| GitHub token (опционально) | GitHub MCP | если нужны issues/PR из агента |

## Прежняя заготовка установки (не запускать целиком в рабочей среде)

```powershell
winget install Gyan.FFmpeg
uv venv
uv pip install numpy pandas soundfile jiwer faster-whisper onnxruntime
# опционально, для диаризации:
uv pip install torch --index-url https://download.pytorch.org/whl/cpu
uv pip install pyannote.audio
```

Перед установкой тяжёлых пакетов проверь, сколько займут wheels и модели. Для `pyannote` нужен `HF_TOKEN`.
