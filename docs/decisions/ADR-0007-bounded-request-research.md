# ADR-0007 — ограниченная доработка исследовательского поручения

13.11.2026. Принято по прямому запросу владельца. `closes: LG-2026-11-13-03`.
Не изменение дорожной карты или научных результатов. Дорабатывает ADR-0005.

## Проверенная причина

Независимый reviewer подтвердил: critic есть при явном run, но request PLAN
останавливался на revise; первые URL брались без собственного отбора; две цитаты
могли быть с одной страницы. Предыдущая формулировка «критик не проверяет полноту»
была слишком категоричной: цель/requirements/честность уже разрешали оспорить
недостаточный охват. Уточнены явные критерии покрытия и обратная связь, а не
создан «ещё один критик» ради числа агентов.

## Решение

1. Для новых research-карточек явный research_policy: темы, общий cap запросов
   до 6, до 3 страниц на запрос, до 1 коррекции запросов плана, до 1 раунда
   добавочного поиска, до 2 суммарных попыток автора. Минимумы URL/доменов и
   матрица тем проверяются кодом, смысл/достаточность — независимым REVIEW.
2. Команда оформления предписывает короткую проверку карточки reviewer до
   согласования. Это инструкция UI-агенту, не новое машинное approval и не
   доказательство фактического вызова. Программные ворота критика остаются.
3. Planner предлагает только queries/reason. Builder заново создаёт команды из
   шаблона; нельзя менять поручение, requirements, closes, бюджеты, права записи
   или готовые результаты. Каждая исполнимая версия проходит независимого critic.
4. REVIEW может предложить SEARCH по пробелу. После проверок капов/receipts
   добавляются только новые команды сбора, а старые принятые источники не
   запускаются повторно. Если времени/источников/квоты не хватает — остановка,
   не успешный обзор из памяти. Ошибки текста исправляются в общем лимите автора.
5. Цепочка research-plan-NN.json в изолированном run связана с immutable карточкой
   и предшественником; approval и inputs связывают версии с доказательствами.
   Legacy без policy не расширяет разрешения/расход молча.
   Pending marker, атомарный plan и сохранение STATE перед удалением marker
   обеспечивают fail-closed при прерванном обновлении, не автоматическое recovery.
   Контролёр проходит строгую проверку JSON/типов. Все использованные цитаты
   передаются REVIEW отдельным пакетом с окружающим текстом; переполнение или
   отсутствие цитаты не маскируется усечением и не даёт PASS.
6. Из первых 20 результатов собственный детерминированный отбор: безопасный URL,
   дедуп, релевантность и разнообразие доменов. Manifest сохраняет причины.
   Подсказка docs/repository/arxiv не подтверждает научную первичность или правоту.
   Количество fetch URL не превышает cap, ошибки и незапрошенные ответы не доказательства.
7. Одно явное сообщение владельца может и согласовать показанные рамки, и разрешить
   один запуск. Отдельные согласования для каждой допустимой правки не требуются.
   Само пересланное поручение или /mentor-task не запускают run; отправка/карта/
   новые траты вне рамки по-прежнему требуют человека.

## Почему не просто убрать break / снять лимиты

Свободный replan мог бы подменить поручение, переписать источники или повторить
измерения. Бесконечный поиск расходует квоты и не гарантирует полноты. В новом
маршруте конечный конверт разрешения, типизированные предложения и повторная
критика, а не доверие произвольным командам LLM.

## Проверка и ограничения

Дополнение LG-2026-11-13-04: недостаточное покрытие теперь может быть сохранено
как явный проверенный `partial`, не полное выполнение. Decision указывает
completion_status=partial, limitations и gap для каждой непокрытой темы;
response явно помечен. Все имеющиеся цитаты остаются обязательными проверками.
Только PARTIAL от REVIEW при валидных артефактах даёт task.status=partial и
отдельный исход/пробелы в report/digest. Полные пороги complete не меняются.
Не созданный/не проверенный из-за квоты материал остаётся blocked, а не
получает фиктивный partial или PASS. Карточка/лимиты не изменяются.

Оффлайн-тесты с временными проектами, моделями/страницами-фикстурами и независимое
по контексту (не по семейству модели автора интеграции) ревью кода. 139 unittest
и пять standalone-скриптов прошли; в том числе abrupt-exit Python-процесса в
четырёх точках транзакции. Протоколы — `docs/audits/2026-11-13/`. Живой обзор по реальному
поручению, актуальность найденных работ, поведение провайдеров и фактическая
экономия владельца в этой сессии не проверяются. Не заявлять «полная автономность»
по мокам. Crash recovery, микрофон/внешние согласования и системная изоляция не
исправляются этим ADR. DNS/redirect внешнего fetch требуют отдельной защиты;
URL-фильтр не эквивалент сетевой sandbox. Доменов несколько — не значит исследований
несколько: публикация и зеркало/документация могут описывать одну работу.
