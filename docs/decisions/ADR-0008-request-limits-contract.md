# ADR-0008: единый контракт лимитов research-поручения

Дата: 14.11.2026. `closes: LG-2026-11-13-06`.
Статус: реализовано; независимое ревью не завершено (квота подписки).
Объём карты и согласованные карточки не меняются.

## Причина

В v2 критик смешал использованные и разрешённые followup-раунды, а также
15 минут ответа и 10+15 минут исполнения. Одной правки формулировок недостаточно:
повторные задачи не должны получать новые полные часы.

## Решение

`autonomy/request_limits.py` — общий источник машинных фактов для planner,
критика, REVIEW и отчёта. `counts` содержит allowed/used/remaining; queries
дополнительно planned/unplanned_capacity. Запланированный запрос ещё не расход.
Счётчик расхода увеличивается перед фактическим запуском команды.

- sources: общие 600 секунд initial и followup-сборов;
- answer: общий `time_limit_minutes * 60` для авторских попыток, fallback
  и записи файлов; повторная задача не сбрасывает часы;
- work_total: сумма двух полос (обычно 1500 секунд);
- coordinator: отдельное окно тика (обычно 3000 секунд), включая ворота/проверки;
- ожидание квоты исключается из рабочего времени и продлевает дедлайны.

Каждая критика получает свежий snapshot, не цепочку устаревших снимков.
Счётчики и время проверяются на корректность; поздний результат не принимается.
OpenCode catalog/create/chunk uploads/generate делят один абсолютный дедлайн.
Контракт применяется только при явном research_policy; legacy не получает
дополнительных разрешений.

## Альтернативы

Только пояснить карточку — не обеспечивает общий расход времени в исполнении.
Суммировать полные лимиты повторных задач — ошибочно увеличивает бюджет.
Увеличить квоты/обойти критика — не разрешено и не устраняет неоднозначность.

## Проверка и ограничения

Оффлайн: 194 unittest, в том числе 6 новых интеграционных; отдельно 23 проверки
четырьмя скриптами. Протокол: `docs/audits/2026-11-14/limits-tests.json`.
Это не проверка качества живого обзора или надёжности ночи.
Reviewer не завершился из-за квоты; независимого допуска пока нет.

Клиентский timeout не гарантирует отмену генерации на сервере и абсолютный
billing cap. Учёт сохраняется на границах операций; аварийное убийство процесса
внутри операции не даёт точного её расхода. Повтор run того же ID запрещён,
аварийное продолжение не подтверждено. Ворота/REVIEW не входят в work_total,
но входят в coordinator. Новый run, отправка ментору и изменение карты требуют
своих разрешений; этот ADR их не даёт.
