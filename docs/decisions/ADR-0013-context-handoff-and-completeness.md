# ADR-0013: handoff из состояния и проверяемая комплектность входов

15.11.2026. `closes: LG-2026-11-15-02`. Реализовано; проверка только оффлайн.
Внешние compaction keep/buffer/summary/model/background/warming не меняются.

## Решение

В PLAN/EXECUTE/REVIEW включён `context_audit_enabled`: перед ключевым модельным
вызовом строится детерминированный handoff из STATE/текущей карточки. Содержит
цель/closes/критерии, задачи/статусы/пруф-пути, counters/лимиты/блокировки.
Для обычной ночи runtime task связывается с полной записью task по ID.
DONE процесса не означает accepted outcome. Handoff не разрешает новый запуск,
поиск, запись канонических документов или закрытие этапа. Это состояние, не LLM-summary.

`autonomy/context_packets.py` пишет `WORKSPACE/context/<uuid>.json` до вызова:
хеш точной компактной JSON-сериализации messages, размеры characters/UTF8 bytes,
переданные исходные файлы/SHA, included/omitted и способ отбора. Raw prompt не
копируется в manifest. Исходные ошибки и причины отключения провайдеров в
handoff представлены присутствием/хешем, не raw backend body. Это не DLP для
произвольного текста владельца; в исходные задачи нельзя помещать секреты.

Обязательные agent-context/scope читаются целиком в пределах16k/30k символов,
иначе отказ. STATUS выбирается как header + последовательность ведущих разделов
до первого `## Предыдущее...`/`## Истор...`, не как произвольный prefix4k. Этот
leading current block ограничен16k и не режется. История явно исключена/посчитана;
это соглашение структуры STATUS, не семантический классификатор актуальности.
PROJECT/benchmarks/прочие optional inputs могут оставаться фрагментами, но это
видно в manifest. Подписанные request.json/context.md — обязательные целые входы.

REVIEW получает response целиком<=24k, claims<=160k, decision<=60k, task/checks/
diff JSON больше не режется посередине. Общий пакет ограничен220k символов;
превышение или ошибка записи manifest запрещает вызов, не одобряет неполный
результат. Это не tokenizer и не замена provider-specific input guard.
Для collection REVIEW используется bounded page-aware пакет с omissions/URL/SHA,
а для claims REVIEW — прежний пакет всех цитат. Они не доказывают научную полноту.

Author preflight учитывает handoff до расхода попытки. Окончательный пакет и
manifest успешно готовятся до фиксации счётчика; при предмодельном ContextError
он восстанавливается. Подготовленный пакет передаётся один раз без повторного
добавления handoff. Approved_commands не вызывает модель и не пишет фиктивный
manifest модельного вызова. Квоты/время/receipt/смысловой REVIEW не ослаблены.

Внешняя сессия: ручная `/checkpoint` сохраняет `docs/session-handoff.md` и
SHA первичных документов. После компактизации/новой сессии сначала сверяются
хеши; устаревший handoff не разрешает действия. Автоматический hook стандартной
компактизации не заявляется. Модель-компактор остаётся прежней до калибровки.

## Альтернативы и ограничения

Увеличить keep/окно/частоту summary — не решает срезов night input. Native
checkpoint привязывает к модели/провайдеру, качество/расход не измерены.
Молчаливо отбрасывать checks/конец JSON ради бюджета — отвергнуто.
Автоматически расширять лимиты/повторять автора — отвергнуто.

Manifest не криптографическая подпись и не доказательство того, что модель
усвоила сообщение. Инструкции браузерных источников остаются недоверенными
данными. Role-JSON upload OpenCode-адаптера не переделан в этой задаче.
Гарантируется проверяемый локальный пакет/блокировка, не отсутствие смысловых
потерь LLM. При слишком большом актуальном блоке нужен редактор/разделение
задачи, а не автоматическое исключение ограничений.
