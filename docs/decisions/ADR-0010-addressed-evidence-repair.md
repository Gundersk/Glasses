# ADR-0010: адресная диагностика и авторский evidence-пакет

14.11.2026. `closes: LG-2026-11-14-02`. Статус: реализовано и проверено оффлайн;
новый живой обзор после изменения не запускался. Обязательства карты не меняются.

## Причина

v5 исчерпал две авторские попытки, но остался blocked: C02 — отсутствующая цитата,
C03 — отсутствующий URL. Префикс JSON источника не гарантировал показ всех страниц.
Общая ошибка без claim ID и обрезанный feedback затрудняли адресное исправление.
При этом буквальное совпадение шести других цитат не подтверждало всех частей claims.

## Решение

1. `claim_validation.validate_claims` за один проход проверяет до30 claims:
   уникальность/использование ID, статус, разрешённый evidence, точный URL,
   дословную цитату с нормализацией только whitespace. Ошибки агрегируются
   в `ClaimValidationError.diagnostics`: ID, codes, URL, evidence_file.
   Метаданные ограничены с явной маркировкой; тексты страниц/цитат в ошибку не попадают.
2. Новые планы используют typed acceptance `mentor_response`, не shell-команду.
   `verify` вызывает API напрямую, не теряет stdout и не оставляет только хвост
   traceback. ID привязан к доверенному request_id текущего runner-конфига.
3. Детерминированно некорректный ответ возвращается на EXECUTE без затрат на
   семантический verifier. Полный `validation_feedback` хранится отдельно от
   3000-символьных заметок. Ошибки REVIEW-пакета всегда заменяют устаревший feedback.
4. `author_evidence.author_bundle` заменяет источник-JSON-префиксы: все выбранные
   страницы представлены точными URL/путями/хешами и непрерывными фрагментами
   нормализованного сохранённого текста, offsets и явным числом пропущенных символов.
   Пакет <=60000 символов, распределение по страницам сбалансировано. Если даже
   метаданные и минимальные фрагменты не помещаются — отказ до вызова автора.
5. При ремонте предпочтительны сохранённые цитаты/ключевые слова прежних claims;
   неверная структура прежних claims не блокирует базовый пакет. Цитата через
   границу prefix сохраняется непрерывной, если помещается в бюджет.
   Не найденная цитата не генерируется. Неавторизованные/перенаправленные пути
   и некорректные источники отклоняются. Источники не редактируются.
6. Финальный смысловой REVIEW, полные критерии/partial, квоты попыток и часы
   не ослабляются. Наличие цитаты не доказывает каждую часть claim. Инструкции
   требуют сужать вывод либо явно отмечать unverified/gap.

Дополнительно по ревью: проверены тип списка decision.options и его элементов,
запрещено перенаправление трёх выходных файлов до их чтения.

## Альтернативы

- Увеличить весь контекст: дороже, не решает адресность и не доказывает смысл claims.
- Увеличить попытки/поиск: нарушает прежние лимиты, переносит дефект в следующий run.
- Ослабить matching или принять шесть совпадений как смысловой PASS: отвергнуто.
- Вручную поправить v5 и поменять verdict: отвергнуто; производная редакция отдельно.

## Проверка и границы

281 unittest +23 standalone-проверки PASS, два ограниченных статических reviewer
PASS после исправлений. Reviewer тесты не запускали; независимость по семейству
моделей не гарантируется. Протокол `docs/audits/2026-11-14/evidence-repair-tests.json`.
Read-only v5: обе ошибки названы одним проходом, пакет12 страниц/59999 символов;
хеши82 файлов неизменны (`evidence-repair-v5-readonly.json`).

Фрагменты не равны полной публикации; сам сохранённый fetch мог быть усечён ранее.
Алгоритм выбора фрагментов — эвристика, не семантический анализ. Не доказано,
что новый живой автор завершит обзор. Новый run/поиск/ручная редакция не запускались,
v5 остаётся blocked. Это ремонт инфраструктуры, не новый научный результат.
