# ADR-0004. Где считать: CPU, GPU (DirectML) или облако

- **Дата:** 2026-11-12.
- **Статус:** предложено; заменяет собой неявный выбор в ADR-0002, где CPU был
  принят «по умолчанию», без сравнения с GPU и облаком.
- **Контекст.** Владелец справедливо спросил, почему выбрана только CPU, если
  на машине есть AMD RX 7700 XT. Проверено 12.11.2026 на этой машине:
  i7-11700KF, 64 ГБ DDR4, RX 7700 XT 12 ГБ.
  - CUDA нет и быть не может: это технология NVIDIA.
  - В `.venv`: `onnxruntime 1.31.1`, доступны только `CPUExecutionProvider`
    и `AzureExecutionProvider`; DirectML не установлен.
  - `sherpa-onnx 2.0.1` принимает `provider` только `cpu`, `cuda`, `coreml`,
    то есть GPU-пути для AMD/Windows у него нет.
  - `torch` и `pyannote` не установлены: диаризационного стека пока нет.
- **Что решаем.** Куда идти до января и что считается основным путём.
- **Предложение.**
  1. CPU — основной и гарантированный путь до января: ASR уже работает,
     при воспроизведении в реальном темпе занимает ~30 % CPU.
  2. GPU (DirectML) — отдельная ветка в отдельном venv (`onnxruntime-directml`
     заменяет пакет `onnxruntime`, поэтому в `.venv` не ставится). Имеет смысл
     только для диаризации: у ASR ускорять почти нечего.
     **Ни одного замера на GPU пока нет.**
  3. Облако — измеряемая альтернатива, не обязательство: `PROJECT.md` §4 относит
     сравнение on-device / cloud / edge / hybrid к «позже», на январь оно не
     требуется. Свой замер возможен только при наличии ключа; публичные клипы
     FLEURS можно отправлять без риска для чьих-то персональных данных.
- **Основание.** `PROJECT.md` §3–4, `ROADMAP.md` (этап 2), `docs/benchmarks.md`,
  проверки окружения 12.11.2026, `docs/sources.md` S025–S034.
- **Альтернативы.** (1) Сразу строить GPU-путь — нет гарантии совместимости
  DirectML с pyannote и нет данных, что выигрыш окупит время. (2) Облако как
  основной путь — требует ключа, бюджета, сети и снимает вопрос приватности
  в пользу «данные уходят наружу». (3) Гибрид — удваивает работу в декабре.
- **Последствия.** Мы не заявляем ни выигрыша, ни проигрыша против облака или
  GPU: сравнений не было. В отчёте допустима формулировка «не измерялось,
  выбор обоснован доступностью и отсутствием обязательства».
- **Точки пересмотра.** 20.11.2026 — по реальным WER и задержкам решить, нужен ли
  GPU-замер. Декабрь — после появления разметки диаризации: если DER/RTF на CPU
  не укладывается в бюджет, проверить DirectML и облако. Журнал предложений —
  `docs/roadmap-changes.md`.
- **Чего этот ADR не делает.** Не меняет `ROADMAP.md`, не утверждает финальный
  аппаратный стек, не обещает работу на физических очках.
