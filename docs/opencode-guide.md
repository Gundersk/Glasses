# Учебный гайд: как настраивать OpenCode V2

Этот гайд — не «единственно правильный способ», а разбор того, как устроена среда проекта, на чём она основана и как её менять, не ломая.

---

## 1. На чём это сделано

### Источники

Я руководствовался:

- официальной документацией OpenCode V2: `https://opencode.ai/v2/docs/` и страницами `config`, `agents`, `models`, `skills`, `commands`, `mcp-servers`, `compaction`, `permissions`, `websearch`, `providers`, `tools`, `references`, `instructions`, `snapshots`, `troubleshooting`;
- машинным индексом документации `https://opencode.ai/v2/llms.txt`;
- JSON-схемой конфигурации `https://opencode.ai/config.json`;
- каталогом моделей `openrouter_models.json` и данными models.dev;
- дорожной картой и сводкой проекта;
- проверками: `opencode debug config`, `opencode debug agents`, `opencode mcp list`, `opencode auth list`, тестовыми запусками агентов.

### Есть ли стандарт

Единого официального стандарта «как настраивать агентную среду» нет. Есть несколько слоёв, у каждого свой статус:

| Слой | Статус |
|---|---|
| Конфигурация OpenCode V2 | Официальная JSON-схема и документация |
| MCP (Model Context Protocol) | Открытый стандарт для инструментов |
| `AGENTS.md` | Де-факто соглашение, поддерживается OpenCode и другими агентами |
| `SKILL.md` | Формирующееся соглашение для навыков |
| Роли агентов, память, маршрутизация | Общепринятые практики, но не формальный стандарт |
| Оценка «качества» модели | Бенчмарки и опыт, единого стандарта нет |

Поэтому «соответствует стандарту» здесь значит:

- конфиг валиден по схеме V2;
- используются документированные поля, а не устаревшие V1;
- MCP настроен по протоколу;
- поведение проверено на практике.

Наша конфигурация использует документированные поля V2: `model`, `default_agent`, `permissions`, `compaction`, `tool_output`, `media`, `mcp.servers`, `websearch`, `agents`, `skills`, `commands`, `experimental`. Устаревшие V1-поля вроде `temperature`, `tools`, `maxSteps` не используются.

## 2. Пять слоёв системы

Держи в голове пять слоёв — так проще не путаться.

1. **Провайдеры и модели.** Кто отвечает: OpenRouter, модели, варианты, цены.
2. **Инструкции.** Что агент обязан знать: `AGENTS.md`, `instructions`, `PROJECT.md`, `STATUS.md`.
3. **Агенты.** Кто работает: primary, subagent, `all`; их модели, права, шаги.
4. **Возможности.** Что агент умеет: встроенные tools, MCP, skills, commands.
5. **Контекст и память.** Что и сколько отправляется в модель, как сжимается, где хранится состояние.

## 3. Где что лежит

### Глобальная и проектная конфигурация

- Глобально: `~/.config/opencode/opencode.json(c)` — для всех проектов.
- Проект: `opencode.json(c)` или `.opencode/opencode.json(c)` — для одного проекта.
- Системно: `%ProgramData%\opencode` на Windows — машинные настройки.

Приоритет: глобальная < проектная < системная. Файлы `.opencode` перекрывают прямые файлы в той же директории. Наш конфиг — `.opencode/opencode.json`.

### Что где у нас

```text
AGENTS.md                     короткие правила, загружаются всегда
PROJECT.md                    замысел и границы, читается по необходимости
ROADMAP.md                    утверждённые этапы
STATUS.md                     текущее состояние
docs/                         гайды, источники, ADR, изменения карты
.opencode/opencode.json       конфигурация
.opencode/agents/*.md         агенты
.opencode/skills/*/SKILL.md   навыки
.opencode/commands/*.md       команды
```

### Переменные

В конфиге можно использовать:

- `{env:NAME}` — подставить переменную окружения;
- `{file:path}` — подставить содержимое файла.

Секреты лучше хранить в переменных окружения, а не в конфиге.

## 4. Модели и стоимость

### Как задаётся модель

- Провайдер и модель: `provider/model`, например `openrouter/openai/gpt-6.1-terra`.
- Вариант: `#high`, `#low`, `#max` — если модель поддерживает.
- В корне конфига `model` задаёт модель по умолчанию, но без варианта.
- У агента можно задать свою модель и вариант.
- `default_agent` задаёт агента по умолчанию для новых сессий.

### Что важно проверять

- Модель реально доступна в каталоге.
- Поддерживает ли она tools, vision, audio/video.
- Какой у неё контекст и лимит вывода.
- Сколько стоит input, output и cache read.
- Как она токенизирует русский текст — точный коэффициент надо измерять.

### Практика

- Дешёвая модель — для рутины, поиска, черновиков.
- Дорогая — для решений, кода, проверки.
- Не сравнивай цены за миллион токенов без учёта длины контекста: 1M у дешёвой модели может стоить дороже, чем 20k у дорогой.
- Кэш промпта снижает цену повторного входа, но не обнуляет её.

## 5. Инструкции и память

### `AGENTS.md`

Это главный файл правил. Он загружается автоматически. Его нужно держать коротким:

- цель проекта;
- границы;
- роли;
- правила источников и измерений;
- структура файлов;
- команды;
- запреты.

Если файл разрастается, детали выносятся в `PROJECT.md`, `ROADMAP.md`, `docs/` и читаются по необходимости.

### `instructions`

В конфиге можно добавить дополнительные файлы:

```jsonc
{
  "instructions": ["CONTRIBUTING.md", "docs/guidelines/*.md"]
}
```

Не добавляй туда большие документы: они будут в каждом запросе.

### Память

Память между сессиями — это файлы, а не чат:

- `STATUS.md` — что сделано, что нет, следующие шаги;
- `ROADMAP.md` — этапы;
- `docs/plan.md` — ближайший план;
- `experiments/` — эксперименты;
- `docs/sources.md` — источники.

Чат между сессиями не переносится. Поэтому после значимой сессии нужно обновить `STATUS.md`.

## 6. Агенты

### Режимы

- `primary` — основной агент сессии.
- `subagent` — вызывается из другого агента, получает свежий контекст.
- `all` — может быть и тем, и другим.

### Что можно задать

- `description` — чтобы модель понимала, когда звать.
- `model` — модель и вариант.
- `system` — системный промпт (в Markdown-агенте — тело файла).
- `permissions` — что можно и нельзя.
- `steps` — максимум шагов.
- `hidden` — скрыть из списка.
- `disabled` — отключить.
- `color` — цвет в UI.

### Главный принцип

Разделяй роли по стоимости и правам:

- дешёвый интерфейс — вопросы и навигация;
- дорогой ментор — решения и код;
- исследователь — поиск и факты;
- компрессор — сжатие;
- ревьюер — проверка;
- инженер — код;
- визуальный агент — картинки и видео.

Не давай дешёвому агенту права менять код и запускать shell, если он для этого не предназначен.

## 7. Взаимодействия

### Кто кого зовёт

У нас:

- `assistant` → `researcher`, `digester`, `vision`, `mentor`;
- `mentor` → `researcher`, `digester`, `reviewer`, `implementer`, `vision`;
- специалисты → не зовут никого.

### Глубина и длинные операции

`experimental.subagent_depth` по умолчанию `1`: субагент не может запускать своего субагента. Это защита от лавины токенов.

Длинные операции — установка пакетов, скачивание моделей, обучение, прогон на длинном аудио — лучше выполнять в **primary `mentor`**, а не через субагента. Субагент подходит для короткой проверки (`uv --version`, `ffmpeg -version`), но многошаговая установка в нём хуже видна и может потерять контекст.

Если хочешь, чтобы ментор-субагент тоже мог звать специалистов, можно поставить `2`. Но это увеличивает стоимость и сложность; по умолчанию не стоит.

### Детерминированные маршруты

Модель может ошибиться в выборе. Если нужен гарантированный маршрут — используй команды:

- `/research` — исследователь;
- `/vision` — визуальный агент;
- `/review` — ревьюер;
- `/mentor` — ментор;
- `/report` — отчёт;
- `/roadmap-change` — изменение карты.

## 8. Skills

Навык — это `SKILL.md` с описанием и инструкциями. Он не занимает контекст, пока его не загрузят.

```text
.opencode/skills/literature-review/SKILL.md
```

В начале файла:

```yaml
---
name: Literature review
description: Как искать источники и собирать доказательства
---
```

Правила:

- `description` должен объяснять, когда навык нужен.
- Тело — короткое и по делу.
- Поддерживающие файлы лежат рядом.
- Если навык не должен предлагаться автоматически, поставь `opencode/autoinvoke: false`.

---

## 9. Команды

Команда — это шаблон запроса. Живёт в `.opencode/commands/*.md`.

```md
---
description: Проверить файл
agent: reviewer
subagent: true
---

Проверь $ARGUMENTS.
```

Поля:

- `agent` — какой агент использовать;
- `model` — модель;
- `subagent` — `true` (дочерняя сессия), `false` (текущая);
- `$ARGUMENTS`, `$1`, `$2` — подстановки.

Команды полезны там, где не хочешь полагаться на решение модели.

## 10. MCP

MCP — стандарт инструментов. Конфиг:

```jsonc
{
  "mcp": {
    "servers": {
      "context7": {
        "type": "remote",
        "url": "https://mcp.context7.com/mcp",
        "oauth": false
      }
    }
  }
}
```

Правила:

- добавляй только те серверы, которые реально нужны;
- каждый сервер добавляет инструменты и расход контекста;
- для локальных серверов нужен `command`;
- для remote может понадобиться OAuth или header;
- таймауты задаются в `mcp.timeout`;
- `codemode` по умолчанию группирует инструменты, это экономит контекст.

У нас подключён только Context7. Tavily, GitHub, arXiv, Playwright можно добавить позже.

## 11. Права и безопасность

Права — список правил:

```jsonc
{
  "permissions": [
    { "action": "read", "resource": "*.env", "effect": "ask" },
    { "action": "shell", "resource": "git push *", "effect": "ask" }
  ]
}
```

Важно:

- правила применяются по порядку, **последнее совпадение выигрывает**;
- глобальные правила идут раньше агентских;
- `*` может перекрыть точечные запреты, если стоит после них;
- для `.env` лучше `ask`;
- `external_directory` — `ask`;
- `shell` — опасные команды `ask` или `deny`;
- субагентам, которым не нужен shell, — `deny`.

Секреты:

- не писать в конфиг;
- не коммитить `.env`;
- использовать `{env:NAME}`;
- проверять `.gitignore`.

## 12. Контекст и память

### Что отправляется

В одной сессии в модель уходит:

- системный промпт;
- `AGENTS.md` и инструкции;
- все сообщения пользователя и ассистента;
- вызовы инструментов и их результаты;
- прочитанные файлы;
- вложения.

Не уходит:

- другие сессии;
- файлы, которые не читались;
- внутренние логи субагентов.

### Компакция

Когда сессия приближается к лимиту, OpenCode суммаризирует старую часть и оставляет последние ~20 тыс. токенов. Это lossy.

```jsonc
{
  "compaction": {
    "auto": true,
    "keep": { "tokens": 20000 },
    "buffer": "12%"
  }
}
```

`buffer` — сколько места оставить свободным. Для 1M-модели 12% — это очень поздно; не рассчитывай на компакцию как на способ сэкономить. Лучше начинать новую сессию под задачу.

### Вывод инструментов

`tool_output` ограничивает строки и байты:

```jsonc
{
  "tool_output": {
    "max_lines": 1200,
    "max_bytes": 48000
  }
}
```

Это спасает от гигантских логов, но 48 КБ — всё ещё токены.

### Медиа

`media.image` уменьшает большие изображения:

```jsonc
{
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 1600,
      "max_height": 1600,
      "max_base64_bytes": 2097152
    }
  }
}
```

Для мелкого текста на скрине может понадобиться 2000 px или кроп.

### Практика

- Новая задача — новая сессия.
- Перед закрытием — `/status`.
- Для тяжёлого поиска — `researcher`.
- Для длинных текстов — `digester`.
- Скриншоты — файлом и через `/vision`, а не вложением в основной чат.
- Большие логи — в файл, потом `grep`.

## 13. Проверка

После изменений:

```powershell
opencode debug config
opencode debug agents
opencode mcp list
opencode auth list
opencode models
opencode stats
```

Что проверить:

- конфиг парсится;
- `default_agent` правильный;
- агенты на месте, модели доступны;
- MCP подключён;
- права не перекрыты широким `*`;
- `.env` требует `ask`;
- субагенты не имеют лишнего shell;
- нет секретов в конфиге;
- `AGENTS.md` не разросся;
- команды и навыки видны;
- тестовый простой запрос и вызов субагента работают.

## 14. Как поручать настройку нейросети

Нейросеть хорошо пишет конфиги, но ей нужен точный бриф. Плохой запрос: «настрой всё хорошо». Хороший бриф:

```text
Цель: настроить OpenCode V2 для проекта <...>.
Контекст: <ссылки/файлы, ОС, железо, бюджет>.
Что сделать:
1. ...
2. ...
Ограничения:
- не менять глобальный конфиг;
- не добавлять MCP без необходимости;
- секреты только через env;
- сохранить существующие настройки;
- использовать только документированные поля V2.
Критерии готовности:
- opencode debug config парсится;
- агенты видны в debug agents;
- mcp list показывает ...
- простой тест и вызов субагента работают.
Проверка:
- покажи diff;
- покажи вывод команд;
- объясни tradeoff;
- предложи rollback.
```

Рабочий процесс:

1. `plan` или `assistant` — план.
2. Ты утверждаешь.
3. `mentor` — реализация.
4. `reviewer` — проверка.
5. Ты проверяешь поведение и стоимость.

Что проверять самому:

- модели и цены;
- права (особенно `.env`, shell, subagent);
- секреты;
- что не добавлены лишние MCP;
- что `AGENTS.md` короткий;
- что новые правила не конфликтуют;
- что тестовый сценарий работает.

## 15. Чего ещё нет и что стоит добавить

### Сейчас

- Локальный git: `git init`, первый commit, `.gitignore` уже есть. GitHub — позже, без тебя не трогаю.
- `requirements.txt` или `pyproject.toml` для Python.
- `ffmpeg` — для аудио/видео.
- HF-токен — для pyannote.
- `ruff` + `pyright` + `pytest` — качество кода.
- `references` на репозитории sherpa-onnx, WhisperLiveKit, pyannote, Light-ASD — чтобы агент читал документацию по необходимости.

### Скоро

- MCP: arXiv (статьи), Tavily (второй поиск), GitHub (issues/PR), Playwright (UI-тесты) — только по мере необходимости.
- Skills: чтение статей, аудит лицензий датасетов, ASR-бенчмарк, шаблон отчёта.
- Мониторинг расходов: `opencode stats`, простая таблица стоимости экспериментов.
- Security: проверка секретов, политика `.env`, ревью прав.
- Backup: git + внешнее хранение данных.
- Experiment tracking: сначала файлы, позже MLflow/DVC, если станет тесно.

### Позже

- CI на GitHub Actions.
- Публикация отчётов/демо.
- Автоматические бенчмарки ASR/диаризации.
- Мониторинг качества моделей на русском.

## 16. Рекомендуемый режим работы

Ежедневно:

1. Новая сессия.
2. «Где мы остановились?»
3. Работа в `assistant`; сложное — `/mentor`.
4. `/status` в конце.
5. Следующая задача — новая сессия.

Еженедельно:

- просмотреть `STATUS.md`;
- проверить расходы;
- убрать лишние MCP/навыки;
- обновить `AGENTS.md`, если правила изменились.

Ежемесячно:

- `/report`;
- проверить дорожную карту;
- при необходимости `/roadmap-change`.

## 18. Главное

- Не нужно быть экспертом по всем полям. Нужно понимать пять слоёв и проверять ключевые вещи.
- Нейросеть может писать конфиги, но бриф и приёмка — твои.
- «Стандарта» на всё нет; есть схема OpenCode V2, MCP и де-факто соглашения.
- Лучшая память — файлы, а не чат.
- Лучшая экономия — короткие сессии, субагенты и дешёвые модели для рутины.
