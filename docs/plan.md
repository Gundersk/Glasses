**Критерий:** команда `ffmpeg -version` работает; Python читает wav и считает длительность.

- [ ] Запустить обе модели на одном аудио.
- [ ] Замерить: время до первого текста, до финала, p50/p95, WER (если есть эталон).

- [ ] Сделать вывод: что работает на этом железе, что нет.

**Критерий:** есть таблица сравнения и честный вывод. Отрицательный результат тоже годится.

## Бюджет и токены

- Рутина и поиск — `assistant` / `researcher` / `digester`, не `mentor`.
- `mentor` — только решения, код и финальный текст.
- `reviewer` — только на финальные проверки.
- Не отправлять сырые страницы в дорогую модель.
- Перед длинной сессией обновлять `STATUS.md`.

## Точки решения

1. Если CPU-ASR не даёт приемлемую задержку — проверить ONNX/DirectML, затем edge/cloud-вариант.
2. Если нет HF-токена — диаризацию отложить, не блокировать ASR.
3. Если нет размеченных диалогов — начать с 2–3 добровольцев, не ждать идеального датасета.
4. Если модель не даёт WER лучше — зафиксировать и сравнить на одном аудио, не подгонять.
5. Если проект начинает разрастаться — вернуться к `ROADMAP.md` и согласовать с ментором.
