Когда изменение действительно понадобится
Триггеры, при которых система обязана поднять вопрос:
Обязательный артефакт невозможно получить на доступном железе или при доступной лицензии.
Обязательное измерение невозможно на выбранных данных (например: нет эталонного текста → WER не считается).
Лицензия источника запрещает предполагаемое использование (ND-корпуса).
Посылка шага опровергнута фактом (модель оказалась не потоковой).
Внешняя работа заняла заявленный вклад, и формулировку актуальности надо сузить.
Срок шага сталкивается с сессией так, что результат под угрозой.
Ни один сейчас не сработал. Все шесть — на будущее.
3. Механизм: система сама сообщает о нужде в корректировке
Один файл + одна строка в дайджесте + готовое письмо ментору. Оркестратор не трогать.
autonomy/workspace/CHANGE_REQUESTS.md — только чтение для тебя, только запись для системы. Формат записи:
### CR-2026-11-001 · статус: ОЖИДАЕТ РЕШЕНИЯ
Пункт карты:   Этап 3, шаг 1 (дословная цитата из scope.md)
Триггер:       2 — обязательное измерение невозможно
Факт:          <что именно, с датой и источником>
Доказательство: workspace/evidence/<run_id>/... или ссылка на первоисточник
Влияние:       какой артефакт этапа не будет получен
Варианты:      A) ничего не менять  B) сузить  C) заменить  D) перенести
Рекомендация:  A/B/C/D + почему
Цена:          что теряем при каждом варианте
Письмо ментору: <готовый текст, 5–7 строк, можно отправить как есть>
Правила, которые надо вписать в AGENTS.md:
Система никогда не редактирует docs/scope.md, PDF и ROADMAP.md по своей инициативе. Только предлагает.
При срабатывании триггера — запись в CHANGE_REQUESTS.md + строка в digest.md: ⚠ CR-001 ожидает решения: этап 3 шаг 1.
Вариант «ничего не менять» обязателен всегда. Отсутствие изменений — нормальный исход, а не отсутствие работы.
Утверждения вида «нет ни у одного / ни в одном» получают тот же статус проверки, что и числа: подтверждено / не проверено / опровергнуто + источник + дата. Без этого — не попадают в отчёт.
Задача не может считаться закрытой, если не отмечен обязательный артефакт этапа из чек-листа, а не только метрика.
Чек-лист артефактов — новый файл docs/artifacts.md, дословно из PDF, с полем «требует человека». Это лечит главный перекос: сейчас планировщик видит задачи, но не видит, что оценивается.

НАЧАЛО ПРОМПТА
Ты проектируешь слой целеполагания и отчётности для автономной исследовательской системы. Сегодня 13 ноября 2026. Проект — дорожная карта УрФУ «Система субтитров с определением говорящего для умных очков», участник Антропов Ю. А. (РИ-160943), ментор Летавин Д. А. Жёсткие ограничения
Не переписывай утверждённый PDF и docs/scope.md. Источник обязательств — только они.
Не изобретай обязательства. В текущем ROADMAP.md уже есть фантомные: «сравнить с аудио-only» (этап 4), «оформить статью» (этап 5), «UX-тесты» (этап 6) — в PDF их нет. И потеряны реальные: «при разных условиях», «расход ресурсов», видеодемонстрация и таблица измерений как артефакт этапа 2.
Каждое число — с provenance: источник, дата, run_id или ссылка. Число без артефакта в отчёт не попадает.
Утверждения «нет ни у одного / нет ни в одном» требуют статуса проверки, как метрики.
Ничего не обучаем с нуля — исключено PDF. Fine-tune на первом этапе не делаем.
Не предлагай изменений карты без сработавшего триггера. Отсутствие изменений — нормальный результат.

Задача 2. Механизм корректировок
Создай autonomy/workspace/CHANGE_REQUESTS.md и логику его заполнения. Схема записи: пункт карты (дословная цитата) → триггер → факт с датой и источником → доказательство → влияние на артефакт → варианты A «ничего не менять» / B «сузить» / C «заменить» / D «перенести» → рекомендация → цена каждого варианта → готовое письмо ментору на 5–7 строк.
Триггеры: (1) артефакт невозможен на доступном железе/лицензии; (2) обязательное измерение невозможно на выбранных данных; (3) лицензия запрещает использование; (4) посылка шага опровергнута; (5) внешняя работа заняла заявленный вклад; (6) срок сталкивается с сессией.
