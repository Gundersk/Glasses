# autonomy/ — ночная автономная исследовательская система

Принцип: **оркестратор — код, модели — работники.** `verify` и контролёр проверяют
задачу, но PASS не доказывает корректность научной методики и происхождение данных.

**Состояние на 13.11.2026:** исправлены защитные ворота и добавлены протоколы
исполнения. Проверены локальными тестами, НЕ живой ночью. Прочитать
`docs/autonomy-audit-2026-11.md` перед запуском. Никакого старта без прямой команды
владельца; текущий допуск — только подготовка одного ограниченного smoke, не супервизор.

## Задание от ментора (новый ограниченный маршрут)

Исправление 13.11: TinyFish `fetch_content` теперь принимает документированное
поле `text` и сохраняет его в canonical `sources[].content`; ошибки MCP/schema и
безопасные коды отказов не подменяются пустым успехом. Сбор команд поручения
прерывается на первой ошибке. Live smoke 3/3 известных страниц, не новый обзор:
`docs/audits/2026-11-13/fetch-fix-tests.json`. Exa в Python-роутер не включён:
стоимость subprocess-вызовов пока не привязана к бюджету ночи/карточки.

Инструкция — `docs/mentor-requests.md`, команда OpenCode `/mentor-task <текст>`.
Она оформляет задание, **не запускает ночь**. `autonomy.intake submit` сохраняет
карточку без сети/LLM; `run <id>` — отдельный явный запуск после команды владельца.
Пример `workspace/requests/examples/analogues.json` — заготовка, не активное поручение.

Маршрут: план под immutable карточку → критик → свежие источники с receipt →
response/claims/decision → проверки цитат и структуры → независимый сильный REVIEW
(лестница критика) → отчёт. STATE/план/вердикты/цели/логи/кэш изолированы под
`workspace/requests/<id>/run/`, общий lock не допускает параллельную обычную ночь.
Ответ — `reports/mentor/<id>/`. Автор не пишет источники и служебные файлы,
не выполняет команды; канонические цели/карта не меняются. Код/измерения этим
документным маршрутом не запускаются. Повтор id и произвольный auto-replan запрещены.
С явным `research_policy` разрешены одна коррекция запросов и один дополнительный
раунд поиска в общем cap, с новой критикой и сохранением прежних receipts.
Контроль покрытия тем/разных URL/доменов не заменяет смыслового REVIEW. Для legacy
без policy новые разрешения не включаются молча. См. ADR-0007 и подробную инструкцию.
Недостаточно покрытый, но честный и проверенный материал может закончиться
отдельным `partial` (не `done`): маркировка, явные пробелы, проверки цитат и
REVIEW=PARTIAL. Отчёт/digest различают complete/partial/blocked. Без доступной
проверки остаётся blocked с сохранёнными черновиками, не фиктивный успех.
Владельцу достаточно одного сообщения, явно согласующего показанные лимиты И
разрешающего один run; сама команда /mentor-task остаётся оформлением без старта.

Проверки ПО — `docs/audits/2026-11-13/offline-tests.json`; живое качество ответа
ещё не проверено. Не запускать обычный preflight перед intake run и не путать
отдельную карточку с разрешением запустить супервизор.

## Как запустить

```powershell
# разовый прогон (как будто ночь):
.venv\Scripts\python.exe -m autonomy.runner tick

# состояние:
.venv\Scripts\python.exe -m autonomy.runner status

# разрушительный сброс STATE + night_plan; только после сохранения и согласования:
.venv\Scripts\python.exe -m autonomy.runner reset

# безопасные локальные регрессии без рабочего STATE и живых моделей:
.venv\Scripts\python.exe -m unittest autonomy.tests.test_intake autonomy.tests.test_safety_gates autonomy.tests.test_provider_contracts autonomy.tests.test_evidence -v
```

`AUTONOMY_MOCK` подменяет модели, но НЕ изолирует файловую систему и НЕ запрещает
команды из загруженного плана. Не применять `tick` в mock-режиме как безопасный тест
рабочего каталога. Mock-одобрение v3 не подходит реальному режиму и наоборот.
Strata/Gemini в текущие лестницы ролей не входят; список — `config.yaml`.

## Запуск по команде

Сам по себе цикл не стартует: ни по расписанию, ни при входе в систему. Пока нет
команды, ничего не происходит.

Один тик вручную:

```powershell
.venv\Scripts\python.exe -m autonomy.runner tick
```

Непрерывная работа после ручного старта: супервизор сам повторяет `tick`, пока не
будет `DONE`, пока не появится `workspace/STOP` или пока три тика подряд не упадут.

```powershell
powershell -ExecutionPolicy Bypass -File autonomy\scripts\start_night.ps1
```

Супервизор запускается отдельным процессом и переживает закрытие терминала. Он
пишет `workspace/supervisor.pid`, журнал `workspace/scheduler.log` и не создаёт
задач планировщика Windows.

Остановить:

```powershell
# попросить остановиться после текущего тика
powershell -ExecutionPolicy Bypass -File autonomy\scripts\stop_night.ps1

# остановить сразу, не дожидаясь текущего тика
powershell -ExecutionPolicy Bypass -File autonomy\scripts\stop_night.ps1 -Force
```

Задача `OpenCodeGlasses-NightRunner` и скрипт `install_trigger.ps1` удалены.
Не создавать их снова: автоматический старт запрещён требованием владельца.

## Preflight (обязателен перед ночью)

Это не read-only проверка: меняет состояние и вызывает внешние модели. В текущий
оффлайн-аудит не входит; запускать только по согласованной команде владельца.

`autonomy/scripts/preflight_night.ps1` вызывает `python -m autonomy.preflight`, который:

- сбрасывает `STATE.json`, если прошлая ночь завершена (`DONE`/`FAILED`) — иначе tick
  выходит за 0 секунд и ничего не делает;
- не восстанавливает план из `night_plan.backup.yaml`, если в нём нет задач к работе;
- пробует неподписочные провайдеры коротким запросом (`night.probe_max_tokens`) и
  отключает мёртвые до утра. Недоступный эндпоинт (сеть, ключ, регион, квота) — это
  «мёртв»; живая модель, ушедшая в reasoning, — нет, её поймает обычная проверка;
- проверяет `autonomy/goals.yaml`: валидность, наличие открытых целей и то, что все
  файлы-доказательства целей существуют. Отсутствующее доказательство — FAIL;
- проверяет, что разбор команд не съедает обратные слэши Windows и `\w` в regex.

## Машина состояний

```
IDLE → PLAN → КРИТИК → (правки → КРИТИК) → EXECUTE → VERIFY → REVIEW → MANAGER → EXECUTE
                     ↑                  ↘ REPAIR (ESCALATE/цикл) → EXECUTE/REPORT
                     └── FAIL ────────────┘        REPORT → DONE
```

## ChatGPT-подписка (13.11.2026)

Используется **уже подключённый аккаунт** OpenAI в OpenCode, повторный вход
не нужен. Активные платные GPT-маршруты заменены на `openai/...`; резерв
API GPT удалён. Kimi остаётся первым у mentor/critic, Sol — сильный резерв,
Terra medium — автор/планировщик; короткие служебные роли остаются дешёвыми.
Подробности и ограничения: `docs/decisions/ADR-0006-chatgpt-subscription.md`.

- Вызовы через штатный `opencode api`, отдельная сессия, `/generate` без
  инструментов. Секреты не копируются. Подписочная генерация пока **не запускалась**.
- При квоте — разрешённая альтернатива, затем ожидание внутри того же вызова:
  известный reset + минута; неизвестный короткий — около 5 ч 6 мин; один повтор.
  Неизвестный недельный сброс — остановка, не цикл каждые пять часов.
- Ожидание максимум 6 часов; сохраняются heartbeat/STATE/счётчики. STOP прерывает
  ожидание. ПК должен оставаться включённым и не спать. Перезапуска после сбоя/
  перезагрузки нет: прежние защитные ворота recovery сохраняются.
- Общий журнал квоты `autonomy/workspace/subscription.sqlite3` не коммитится и
  не сбрасывается вместе с STATE отдельного задания. Не удалять его ради обхода cap.
- Контекст берётся из каталога выбранной модели, не из лимита OpenRouter.
  Auto summary, keep 24k, buffer 20%, warming off; для ночных задач — свежий
  ограниченный вход вместо разрастающейся истории. `docs/agent-context.md` и
  STATUS — опорные файлы, не надежда на безошибочную компактизацию.
- Остаток Plus, качество ответа и настоящий сброс квоты **не измерены**.
  Внутренние retry OpenCode могут добавлять физические запросы сверх нашего
  учёта; локальные caps — предохранитель, не гарантия расхода подписки.

## Фазы и ворота

- **КРИТИК** (`autonomy/critic.py`, `kimi_pro` → `chatgpt_critic`) — ворота перед
  выполнением. Он не правит файлы и не выполняет работу: проверяет цель,
  измеримость приёмки, условия сравнения метрик, бюджет времени против тика,
  отсутствие человеческих действий, ценность артефакта для защиты и честность
  обещаний. Вердикт `approve / revise / block`; при `revise` планировщик
  переписывает план с замечаниями и план уходит на повторную критику, но не
  больше 2 раундов. `block`, исчерпанный `revise`, невалидный/недоступный ответ
  останавливают выполнение и выносят решение владельцу. Замечания пишутся в
  `workspace/outbox/critique.md`, вердикт и раунды — в `STATE.json` (`critique`).
  Model ID критика отличается от автора (не только алиас); это не гарантия качества.
  Критик может запросить внешний факт (`needs_search`, до 3 запросов): выжимка
  TinyFish уходит ему в контекст, ответ — повторный. Раунд поиска один, иначе
  критика превращается в исследование. Сбой запрошенного поиска блокирует план;
  превышение лимита/повторный поиск — тоже. Лимит вывода — 24k (для новой лестницы
  пока не калиброван). Одобрение v3 связано с планом, контекстом и mock-режимом;
  правка задачи/политики требует новой критики, служебные статусы хэш не меняют.

- **PLAN** — планировщик (`chatgpt` → `deepseek1017` → `qwen38_flash`) получает реестр целей,
  `PROJECT.md`, `STATUS.md`, `digest.md` прошлой ночи и хвост согласованных RC.
  Прошлый отчёт он больше не читает: его заменил digest, посчитанный кодом.
  Каждая задача обязана ссылаться на `goal_id` открытой цели. Если открытых целей
  нет — ночь останавливается и просит решение о следующем этапе.
  Если night_plan.yaml свежий (<12ч) и в нём есть pending-задачи — используется он.
  Планировщик/критик также видят дословный раздел текущего этапа из scope:
  машинные метрики не заменяют обязательные микрофон/инструкцию/видео/таблицу.
- **EXECUTE** — исполнитель (`chatgpt` → `deepseek1017` → `qwen38_flash`;
  ChatGPT medium, у API-резерва reasoning выключен)
  получает одну задачу и отвечает строго JSON `{files, commands}`. Runner сам пишет
  файлы и запускает команды — модель руками не делает ничего, только предлагает.
  Для `kind: measurement` обязателен `execution: approved_commands`: выполняется
  точный список команд одобренного плана БЕЗ LLM-исполнителя. Команды всё ещё имеют
  права текущего пользователя — это не системная изоляция.
  Итерации ограничены (`max_iter`), ошибки предыдущих итераций подсказываются.
  Содержимое с маркерами заглушки не записывается, прежняя версия файла сохраняется
  в `workspace/backups/`.
  Бюджет задачи (`time_limit_minutes`) проверяется кодом: команда ограничена
  остатком бюджета и убивается вместе с деревом процессов, а задача не стартует,
  если в тике осталось меньше `time_limit + 2` минут. Такая задача помечается
  `deferred`, попадает в отчёт и возвращается в `pending` на следующую ночь.
- **VERIFY** — `verify.py`: детерминированные проверки acceptance + манифест-дифф
  (что реально изменилось; «ничего не изменила» = fail). Для approved_commands —
  receipt v2: точное число/порядок/хэши команд, успешные коды, полные stdout/stderr
  с редактированием известных секретов, хэши заявленных входов, свежесть ВСЕХ файлов
  из file_exists/json_eq/number_range/regex_in_file. Произвольный `command` в приёмке
  непрозрачен: каждый читаемый им результат надо отдельно объявить файловой проверкой.
  Вердикт сохраняется в `workspace/verdicts/`, привязан к задаче/режиму/артефактам.
- **REVIEW** — независимый контролёр (`glm53_flash` → `deepseek1017`): PASS/FAIL/ESCALATE.
  Стоит на другой модели, чем исполнитель, чтобы не быть самопроверкой. PASS при
  непройденном verify.json игнорируется. Перед приёмкой заново сверяются привязка
  вердикта, файлы и receipt. Замена/изменение после VERIFY блокирует приёмку.
- **MANAGER** — менеджер (`deepseek1017` → `qwen38_flash`) не выполняет работу:
  двигает статусы целей, принимает уроки и решает, нужен ли человек. Доказательства
  целей добавляет код по связанному verify, а не модель. Полное закрытие цели
  требует подтверждения владельца; модель не закрывает критерий этапа одним файлом.
  Уроки пишутся в `workspace/lessons.md`.
- **REPAIR** — ментор (`kimi_pro` → `deepseek1017`): continue/replan/halt. Ответ не в
  JSON не останавливает ночь: один повтор с требованием формата, затем «продолжай».
- **REPORT** — факты ночи считает код (`facts.json`), свободная модельная
  интерпретация отключена (`report_interpretation_enabled: false`): проверка одних
  чисел не защищает от выдуманных выводов. Отчёт версионируется:
  `outbox/reports/<night_id>.md`, плюс `outbox/report.md` и `workspace/digest.md`.

## Цели и доказательства

`autonomy/goals.yaml` — машинный реестр: глобальная цель, текущий этап, критерии
этапа и локальные цели. Планировщик видит открытые цели; задача без `goal_id`
или с неизвестной/закрытой целью отклоняется. Нужны валидный `closes` и непустая приёмка.

- Доказательства цели добавляет код по `verify.json` (только `file_exists`,
  прошедшие проверку), а не модель.
- Модельные обновления `done`/закрытия цели отклоняются даже при наличии файла.
- `blocked` без причины отклоняется.
- Если открытых целей нет, этап закрыт или цель не получала доказательств
  `max_nights_without_progress` (3) ночей подряд — ночь останавливается и выносит
  решение владельцу вместо бесконечных прогонов.
- Человек всегда решает: изменение ROADMAP, публикацию, деньги, credentials,
  живую запись с микрофона и демонстрацию.

## Границы песочницы (config.yaml → sandbox)

- Писать можно только в: `autonomy/workspace/**`, `experiments/**`, `reports/**`,
  `docs/research/notes/**`, `data/interim/**`, `STATUS.md`.
- Запрещённые команды (rm -rf, реестр, планировщик, сети-на-выполнение) — reject +
  violation в отчёт. Попытка записи вне песочницы — то же самое.
- Это **прикладная**, не системная защита: жёсткая изоляция — отдельный пользователь
  Windows + ACL (следующий этап, см. STATUS.md).

## Единые лимиты research-поручения

ADR-0011: policy-сбор использует --allow-unavailable и typed research_collection.
Известная недоступность URL пишет schema-v2 manifest и продолжает оставшиеся
разрешённые запросы. Неизвестная/MCP/auth/rate/schema ошибка остаётся fatal.
sources=[] не evidence; нужны реальные страницы, прежние checks и REVIEW.
Selected/query caps сохраняются, новые readers/URL/поисковые модели автоматически
не вызываются. `docs/audits/2026-11-14/fetch-alternatives.md` — диагностика
TinyFish/Exa, не причина включать платный fallback. Legacy no-pages по-прежнему error.

ADR-0010: ответ новой карточки проходит typed `mentor_response` без subprocess;
все ошибки цитат агрегируются по claim ID. Полный validation_feedback отделён
от коротких заметок. Источники автору: `author_evidence.author_bundle` <=60k,
все выбранные страницы/URL/хеши, offsets и явные omissions. Некорректный источник
блокирует вызов автора; некорректные prior claims не блокируют базовый пакет.
При FAIL не тратится семантический verifier; при успешной машинной проверке
смысловой REVIEW по-прежнему обязателен. Никакого расширения попыток/поиска.
Протокол: `docs/audits/2026-11-14/evidence-repair-tests.json`.

Вспомогательные browser-модели: `python -m autonomy.assist digest|scout`,
по умолчанию dry-run, `--execute` разрешает один вызов; `--browser-only`
отключает API fallback. `--wait-seconds 60` разрешает малую обычную паузу.
`status` читает локальный ledger без сети. Политика: `browser_models.yaml`,
ключи только env; SQLite общий между изолированными карточками, исключён из git.
Использовать по `docs/browser-models.md`/ADR-0009, не внутри квотированного поиска
карточек и не вместо critic/verifier. Live пока blocked; модели не калиброваны.

ADR-0008: `request_limits.snapshot` сообщает planner/critic/REVIEW и отчёту
allowed/used/remaining, отдельно planned запросы. Для research_policy часы общие:
sources=600 секунд для initial+followup; answer=time_limit_minutes карточки
для всех авторских попыток/fallback/записи; work_total — их сумма. Coordinator
отдельно включает ворота и проверки. Subscription wait не рабочее время.
Повторная задача не получает новый полный бюджет. Клиентский timeout не
гарантирует отмену серверной генерации; аварийный resume не подтверждён.
Оффлайн-протокол: `docs/audits/2026-11-14/limits-tests.json`; независимое ревью
не завершено, допуска к живому run эти тесты не дают.

## Бюджет, лимиты и reasoning

- `night.budget_usd_per_night: 1.0` — платные провайдеры отключаются при исчерпании.
  Это локальная защита, НЕ абсолютный billing cap. Для него нужен лимит у провайдера.
- Лимиты проверяются перед каждой физической попыткой, включая повтор после
  обрезки; неудачи учитываются в `attempts_by_provider`. Kimi — максимум 8 попыток
  на весь прогон. ChatGPT — общий предел 10 попыток за запуск / 60 за скользящие
  7 суток (включая изолированные задания), автор до 6 / контроль до 4.
  Это локальная политика, не измеренный остаток Plus. Подписочная цена 0 не означает безлимит.
- `role_limits.<role>.max_tokens` — потолок вывода на роль: planner 32k, executor 48k,
  verifier 8k, manager 16k, reporter 16k, mentor 32k, critic 24k. Лимит задаёт роль, а не вызов:
  автору файла нужен запас, контролёру — нет.
- Reasoning выключен (`reasoning: {enabled: false}`) у `deepseek1017` и `qwen38_flash`:
  без этого модель тратит весь `max_tokens` на размышления и возвращает пустой `content`
  (проверено 11.11.2026: 12k, 16k и 32k уходили в ноль). У `glm53_flash` reasoning
  обязательный, эндпоинт отвергает отключение, поэтому glm стоит на коротких ролях.
- Пустой ответ и `finish_reason=length` — ошибка провайдера, а не успех. При обрезке
  роутер один раз повторяет вызов с удвоенным `max_tokens` (до
  `night.truncation_retry_cap`), при пустоте сразу переходит к следующему провайдеру.
- `night.provider_fail_limit: 2` — после двух отказов подряд провайдер отключается до
  конца ночи, чтобы мёртвая модель не жгла время на каждой роли.
- Локальный сервер Strata: таймаут 30 мин, **0 ретраев**, health-check, SSE-стриминг.
  В лестницы ролей не входит с 11.11.2026.
- Gemini free исключён из лестниц: региональный блок и исчерпанная квота (11.11.2026).
- Фактическая стоимость ночи 11.11.2026 на deepseek-исполнителе — $0.006–0.012.

## История работы моделей

`events.jsonl` (workspace) — append-only лента всех событий: каждый вызов модели
(роль, провайдер, токены, стоимость, latency, finish), замены по лестнице
(`model_skip`/`model_fail`), старты/финиши задач, вердикты контролёра, действия
ментора, нарушения песочницы, смены фаз. Это «бортовой самописец» ночи.

```powershell
.venv\Scripts\python.exe -m autonomy.history            # лента за сегодня
.venv\Scripts\python.exe -m autonomy.history --all      # вся история
.venv\Scripts\python.exe -m autonomy.history --role planner
.venv\Scripts\python.exe -m autonomy.history --cost     # сводка затрат по провайдерам/ролям
```

Плюс человекочитаемый `NIGHT_LOG.md` (что происходило) и сырые `runs/*.log` (каждый тик).

Факты (статусы, артефакты, бюджет, число проверок) считает код по связанным
`verify_file` в задачах и `STATE.json` и пишет `outbox/facts.json`. Старый
`verify.<id>.json` без привязки не подхватывается как доказательство новой задачи.
Модельная интерпретация отключена. Историческая стоимость в events неполна:
неудачи без поля cost не являются бесплатными. Отчёт
версионируется по `night_id` в `outbox/reports/`, а `workspace/digest.md` хранит
короткую выжимку для восстановления контекста следующей ночью.

## Анти-заглушка

Модель не может «сдать» задачу, признав в машинном артефакте (json/csv), что работа
не выполнялась (`не запускалось`, `asr_launched:false`, `placeholder` и т.п.). VERIFY-фаза
сканирует изменённые json/csv на такие маркеры и принудит `verify=FAIL`, даже если
планировщик задал слабый acceptance. Честные «не измерено» в STATUS.md/заметках не
трогаем — там это норма проекта. Служебные файлы `autonomy/workspace/**` из скана
исключены: в текстах задач есть честные «не измерялось», и это давало ложный FAIL.
Документные claims/decision тоже не сканируются как экспериментальные JSON:
честное unverified не означает подделку измерения; для них работают отдельная
структурная проверка и REVIEW.

Вторая линия — на записи: содержимое с маркерами `placeholder`, `заглушка`, `todo:`,
`fixme`, `not implemented` или пустое не записывается вовсе, а исполнитель получает
ошибку и следующую итерацию. Перед перезаписью существующего файла его копия кладётся
в `workspace/backups/<штамп>/`. 11.11.2026 модель вернула `PLACEHOLDER_FULL_FILE`
и уничтожила рабочий скрипт — эту потерю и закрывают обе меры.

## Известные ограничения (v0.1)

- Незавершённый STATE после обрыва (EXECUTE с текущей задачей, VERIFY/REVIEW/MANAGER/
  REPAIR) при следующем tick уходит в REPORT с запросом проверки. Автоматический
  повтор побочных эффектов/продолжение чужого старого STATE не поддержаны.
- Открытие старого STATE и произвольная ночь после этих патчей не проверены.
  Только свежий PLAN, одна проверенная задача, без супервизора/auto-replan для smoke.
- Receipt не является защищённым журналом и не раскрывает транзитивные входы:
  WAV/веса/импорты надо объявлять/хэшировать отдельно. Обновление mtime не доказывает
  новый научный результат. Редактирование секретов — best effort, логи перед отправкой проверять.

- Локальная модель на IQ3_XXS иногда выдаёт обрезанный/битый JSON — обработано
  (фидбек «компактнее, один файл за итерацию»), но процент брака ненулевой.
- Strata-сервер падал под нагрузкой длинной генерации — лечится рестартом; health-check
  не даёт системе деградировать молча.
- Песочница прикладная (пути/паттерны), не OS-level.
- Ментор не перезапускает Strata сам — это делает человек или внешний watchdog (TODO).
