## 2. Результаты (только измеренное)

### 2.1 Точность ASR на живой русской речи

Корпус: `google/fleurs`, config `ru_ru`, split `test` - публичный, CC-BY 4.0 (S018).
Взяты **первые 50 клипов** (775 доступно), один говорящий на клип, чтение, без шума.
Эталоны - `raw_transcription` из корпуса. WER = (S+D+I)/N, суммирование по корпусу,
N = 1057 слов после нормализации (нижний регистр, пунктуация удалена, `ё→е`).

| Движок | WER | S / D / I | Задержка p50 | p95 | Артефакт |
|---|---:|---|---:|---:|---|
| Vosk small-ru 0.22 | **18.92%** | 143 / 30 / 27 | 11.9 мс (чанк 0.25 с) | 44.8 мс | `experiments/fleurs_benchmark/vosk_metrics.json` |
| sherpa-onnx zipformer-small-ru int8 | **11.35%** | не считались | 236 мс (чанк 0.2 с) | 401 мс | `experiments/fleurs_benchmark/sherpa_metrics.json` |

Команды:
```
python experiments/prepare_fleurs.py
python experiments/benchmark_fleurs_vosk.py
python experiments/benchmark_fleurs_sherpa.py
```
В обоих JSON - по 10 примеров `ref` vs `hyp`.

**Ограничения:** 50 клипов чтения, не спонтанный диалог; выборка не случайная (первые 50
строк); WER самописный, не сверен с `jiwer`; доверительных интервалов нет (n=50 → ±2–4 п.п.);
манифест без SHA-256. Задержки движков **несопоставимы по семантике** (обработка чанка у
Vosk против декодирования у sherpa) - сравнивать между собой нельзя.

### 2.3 Задержка «после конца фразы» (endpointing)

Paced-клип: 8 фраз, паузы 0.8 с. Замерено, сколько аудиосекунд тишины Vosk «съедает» до
выдачи финального сегмента: **p50 = 509 мс, p95 = 995 мс** (n=8, без цензуры).
Артефакт: `experiments/benchmarks/endpoint_latency.json`. Синтетическая TTS-речь; сеть и
браузер не включены.

Итоговое «ожидание после конца фразы» ≈ endpointing + гранулярность чанка (до 250 мс) +
вычисления (~13 мс) - медианно < 1 с, p95 близок к 1 с.

## 4. Ограничения методики

- Все задержки «конец фразы → финал» в §2.4-2.6 - **n=1** по финалам; это не p50 и не
  устойчивая статистика, а единичные замеры.
- В дуплексных прогонах независимые такты ADC и DAC: запись и воспроизведение идут
  на разных клоках. Отсюда -54.7 ppm дрейфа и 298.1 мс лага; сравнивать задержки
  между прогонами на разных тактах нельзя без пересчёта.
- **Тракт микрофон → браузер не измерен.** §2.4 - подача WAV → браузер; §2.5 - файловый
  дуплекс, проверяется прохождение аудио через ASR, а не акустика.
- Один клип (`clip_001.wav`) во всех потоковых замерах. Разные выборки не смешивались.
- Числа T1 (`cpu_percent_avg/max`, `rss_mb_max`) - один прогон на движок, статистики нет,
  CPU-проценты между движками несопоставимы.
- Условия T2 измерены на пяти клипах; p95 задержек при n = 6–9 - не устойчивая оценка,
  а шум цифровой, поэтому переносить эти WER на улицу или дальний микрофон нельзя.
